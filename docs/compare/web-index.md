# askFinz vs traditional search indexes

## Key points

### Where the web knowledge comes from

The web Their index A page of links Owned end to end, and built to send you somewhere rather than to answer you. It was designed decades before anything needed to read pages for meaning.

### Four differences you can check

A traditional index stores what a page links to. Ours stores what a page says, broken into passages that can each be found on their own — which is why an answer can point at the paragraph rather than the homepage.

### Cheap to hold is why it can be cheap to use

Every page held costs storage forever. Keep that small and reading the whole web is a business; let it grow and the index eats the company.

### A summary of page one is not an analysis of the web

A search API hands back a ranked page of results — usually ten or twenty. Wrap those in a model and you get a fluent answer, but it can only ever be about the handful of pages that ranked.

### One call returns the passage, not a list of places to go looking

Anything that reads the web for you — an assistant, an agent, a research tool — needs the text, not the link. With a conventional search API that means two steps: ask for results, then fetch and strip each page yourself.

## Frequently asked

### Isn't building your own index wildly expensive?

It is expensive to start and cheap to run. Storage is what decides that, and ours costs a few kilobytes per page — small enough that holding the whole thing is an ordinary business cost rather than the business itself.

### Can I buy access to the index directly?

Not today. It powers askFinz Search and the apps built on it rather than being sold as a feed. That is a decision rather than a limitation — if there is enough industry interest, it is something we would look at.
